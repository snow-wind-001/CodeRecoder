# 工程审查：备份范围与启动保护

## 结论与范围

生产架构适合当前本地备份产品：MCP 和 Electron 共用 `BackupManager`，监听器只调度检查点，工程会话分别管理状态与 Serena。恢复保留预览确认、实时树校验、安全快照和中断回滚；renderer 通过工程范围受限的 IPC 工作，不直接访问文件系统。

本次审查覆盖备份过滤、快照兼容、启动状态、桌面配置持久化、MCP 参数与 Linux 打包。合入远程已有的 3.1 修复，避免本地旧实现覆盖上游。旧历史管理器仍仅作迁移参考，未重新接入生产入口。

## 问题与处理

| 问题 | 处理 | 验证 |
| --- | --- | --- |
| 实验输出、模型与数据进入大规模基线 | 增加每工程 `backupScope`、`excludePaths`、`includeExtensions`，默认仍为全部文件 | 默认兼容、类型过滤、目录排除、监听与对账测试 |
| 改范围后恢复旧快照可能覆盖已排除文件 | 预览、应用和恢复校验统一过滤；确认令牌绑定过滤配置；恢复日志记录原范围 | 精确/覆盖恢复保留排除内容、配置变化拒绝旧令牌、中断恢复测试 |
| 旧快照排序与当前运行环境不同 | 保留上游按原顺序校验哈希并检查路径唯一性的修复 | 大小写/Unicode/旧清单重启与恢复；真实旧清单只读校验 |
| 基线备份阻塞状态读取和 Serena | 缓存状态立即返回，后台核验请求合并并限频；Serena 独立启动 | 阻塞基线与后台扫描的隔离测试 |
| 建立基线期间可能显示“保护可用/已完整备份” | 显示“正在建立保护/等待核验”，展示上次成功核验时间 | 桌面状态与浏览器检查 |
| 同时写偏好使用同毫秒临时文件名 | 串行写入，临时文件采用 UUID，保留原子重命名 | 固定时钟下并发 20 次保存，确认最后一次配置生效 |
| 两套打包入口与上游安装器路径发生分歧 | 保留安装命令和安装器，MCP 入口统一转发至独立内置 bundle | Debian 元数据、依赖、权限、启动器、MCP 握手和隔离 GUI 启动 |

## 使用与验证边界

- 新工程和已有工程都可选择范围。已注册工程的修改在下次启动保护时生效，现有快照保留。
- “仅代码与文档”依赖文件名/扩展名，不分析文件内容，也不自动采用 `.gitignore`。生成的 JSON、TXT 和代码副本应通过目录排除；文档插图或特殊源码格式可补充扩展名。
- 状态面板展示缓存与核验时间。备份和恢复使用实际扫描与哈希；恢复确认不会依赖界面缓存。
- 大型工程首次备份仍需读盘并验证，基线完成前不宣称自动保护已就绪。
- Serena MCP 握手与具体语言服务可用性分开看待；语言工具链仍取决于本机安装。
- 本次运行环境为 Linux amd64；未声称完成其他操作系统验证。

验证入口：`npm run lint`、`npm test`、`npm run desktop:package:deb`、`npm run desktop:verify-deb -- release/CodeRecoder-3.1.0-amd64.deb`。界面检查覆盖 380px 和 424px 宽度、默认范围、无效路径、注册与保存后重开；GUI 启动检查使用独立临时偏好，不修改真实工程或备份。

本机结果：38 项自动化测试全部通过；编译、类型检查、两套 Debian 包校验、构建产物与解包产物的隔离 GUI 启动均通过。使用本机 Serena CLI 和临时 Python 工程进行真实启动，约 2.5 秒完成 MCP 握手；此结果不代替实际工程各语言服务的验证。

运行中的旧桌面进程不会随源码编译自动更新。更新后须关闭所有窗口并等待进程退出，再运行 `npm run desktop:start`；该命令会同时编译桌面端与内核。单实例机制会把重复启动请求交给旧进程，因此只重新点击图标无法替换仍在运行的旧版本。
