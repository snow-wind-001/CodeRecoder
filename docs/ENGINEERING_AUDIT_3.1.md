# 3.1 工程补齐检查

对照基线：GitHub `origin/main` 提交 `505e984`；检查日期：2026-09-10。

| 基线缺口 | 3.1 补充 | 验证方式 |
| --- | --- | --- |
| 程序栏安装只检查 npm 包，Electron 本体缺失时无法启动 | 下载本体、采用代理、构建后验证 desktop 文件、回读固定结果 | shellcheck、desktop-file-validate、真实桌面启动 |
| 清单生成和读取采用不同路径排序，导致正常快照被拒绝 | 新清单稳定排序；旧清单按记录顺序校验哈希，独立检查路径唯一性 | 中英文区域、大小写及 Unicode 路径，旧清单重启和恢复，重复路径拒绝 |
| 启动保护期间发生编辑时直接失败 | 最多两次完整重试，清理不完整暂存快照 | 注入扫描/复制间修改，验证仅发布正确基线 |
| Serena 只有命令发现，没有下载或依赖准备入口 | 固定官方源码提交、uv/Python 用户级安装、可选 .NET 10、桌面安装按钮 | 本地源码安装、CLI 版本、真实 stdio/HTTP 与符号查询 |
| 新版 Serena 创建多语言配置会等待交互 | 自动保留主要语言；记录可选语言配置步骤 | 非交互混合语言工程、损坏配置备份与修复测试 |
| 桌面子进程未保证发现用户目录中的语言工具 | 为 MCP 子进程补齐用户 bin 路径；版本检查使用真实工作目录 | 桌面集成与运行中 Serena 查询 |
| MCP 名称拼写不一致，建议始终引用源码文件 | 统一 `coderecoder`；安装包建议使用固定 MCP 启动器 | 四客户端配置测试、无源码/外部 Node 的打包测试 |
| 没有 Debian 构建、包校验和标签发布流程 | electron-builder、安装/卸载钩子、校验脚本、GitHub Actions | 元数据、桌面入口、内置 MCP、GUI 启动；远程发布需检查 Actions 结果 |

备份内核、桌面会话与 Serena 分开验证。MCP `initialize` 成功不等同于所有语言服务就绪，应使用工程实际语言的符号查询确认。Windows 专用项目在 Linux 上的 Visual C++ / MSBuild 构建诊断不属于 Debian 包能自动补齐的跨平台能力。

安装包、构建目录、运行日志、用户工程、备份与认证信息不提交 Git；二进制发布使用 Actions artifact 和 GitHub Release。旧版历史管理模块及 shell 工作流仍作为迁移参考，生产入口以 README 所列的备份内核和当前自动化测试为准。
